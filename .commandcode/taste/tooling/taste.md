# Taste

## Environment & tooling
- Works on Windows: use the PowerShell tool for git/shell commands; plain shell commands with `;`/`&` separators get mangled and should be avoided. Confidence: 0.9
- `uv`-based Python helper scripts (e.g. BMad memlog/customization resolvers) are not available on this machine — fall back to manual equivalents rather than blocking on them. Confidence: 0.7
- Git fork workflow: keeps a clean `production` branch as an exact mirror of `main` for contributing upstream, and prefers GitHub-side toggles (default branch, disabling CI Actions) to be done by the user rather than via CLI. Confidence: 0.6
- Prefers sizable feature work on a dedicated branch (e.g. `feat/<name>`) cut from `main`, keeping `main` clean and uncommitted-to during implementation. Confidence: 0.6
- For its own deployment/operational work (dockerization, Makefile, agent tooling dirs), expects the agent to execute the git release steps itself on terse instruction ("commit and push and merge to production") — merging directly onto the `production` branch rather than routing local deployment work through a PR, while leaving upstream contribution branches (and their PRs) untouched. Confidence: 0.5
- This machine's npm global config sets `omit=dev`, so `npm install` never installs devDependencies — use `npm install --include=dev --ignore-scripts` (the husky `prepare` script otherwise fails and aborts the install); as a result test/typecheck gates (vitest, @types) are unavailable until deps are installed. Confidence: 0.9
- Installing with `--ignore-scripts` skips native-module builds — after installing, run `npm rebuild better-sqlite3 node-pty` (plus `node scripts/fix-node-pty.js`) or the server fails to boot on missing `better_sqlite3.node`. Confidence: 0.7
- Wants the app runnable/deployable via Docker Compose wrapped in a Makefile with the conventional targets `make up`, `make down`, `make build`, `make clean` (mirroring compose verbs), and expects the dockerization to be "proper" (idiomatic multi-stage build, healthcheck, persisted data volume, `.dockerignore`/`.env.example`) rather than a minimal one-off. Confidence: 0.7
- Will not let official/upstream-managed files be modified (denied writes into the repo's official `docker/` sandbox templates); prefers additive sidecar files — a root `Dockerfile`, a separate custom compose file, and a Makefile that targets that custom compose explicitly (`docker compose -f compose.yaml`) — keeping official files untouched. Confidence: 0.75
- Treats automated PR-review bot findings (CodeRabbit) as a real quality gate on their open PRs: when CodeRabbit rates a PR "high merge risk", expects the agent to pull up the review comments and push code fixes addressing each flagged issue (rather than ignoring or waiving them), then push so the bot re-reviews. Confidence: 0.6
